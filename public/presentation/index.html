Campus Bus Transit
Live Tracker & Arrival Predictor

A web platform where drivers report their live stop and GPS location, and students see exactly where their bus is, how full it is, and when it will arrive — powered by a Python backend.
Frontend: React + Vite + Tailwind Backend: Python (HTTP API) Live: GPS location sharing

The problem

Students wait, without knowing when the bus will come

Parul University runs many campus buses across Vadodara, but riders have no reliable way to know a bus's real position or arrival time.

  • ⏳

    No live position

    Students stand at stops with no idea if the bus already left or is 20 minutes away.

  • 🚌

    Overcrowding

    No visibility into how many seats are free before the bus arrives.

  • 📞

    Guesswork & calls

    Arrival times are shared informally over phone calls and word of mouth.

  • 🗺️

    Expensive GPS systems

    Commercial fleet-tracking hardware is costly to install on every bus.

Our solution

A driver-reported, GPS-optional tracking system

Drivers update their current stop and can share live GPS with one tap. The Python backend predicts arrival times from average speed and traffic — no expensive hardware required.

  • 📍

    Manual stop reporting

    Driver taps "Reached next stop" — works even with no GPS signal.

  • 🛰️

    One-tap live GPS

    Optional real-time location streamed to riders on a live map.

  • ⏱️

    Predicted arrival

    ETA to every stop, computed on the Python server from average speed.

  • 💺

    Seats & speed

    Riders see live seat count and average speed before boarding.

System design

Architecture

A React single-page app talks to a Python HTTP API. When published as a static site (no server), it transparently falls back to an identical in-browser engine — so it always works.

Frontend

React + Vite

Departure board, Track, Driver console & Feedback. Polls the API every 3 s and shares GPS via the browser Geolocation API.

⇄
API

Python backend

server/app.py serves buses, routes & feedback and computes average speed + arrival predictions. Vite launches it automatically.

⇄
Fallback

In-browser engine

Mirrors the exact same data & maths so the published static site works with no server running.

The maths (done in Python)

How arrival time is predicted

effective speed = avg(driver's reported speeds) × traffic multiplier

arrival time = ( distance remaining ÷ effective speed ) × 60 min
Distance remaining is measured from the stop the driver last reported — no GPS needed for the prediction. The server keeps a rolling history of reported speeds, so the average smooths out sudden changes. This transparent model can later be swapped for a machine-learning model trained on historical GPS + traffic data.
